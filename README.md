# S07. Учебное API «Внутренний трекер обращений»

Объект `s07-access-control` содержит намеренные дефекты авторизации. Запускайте его локально на `localhost` с учебными данными. На S07 мы определяем, какие действия допустимы для конкретного пользователя над конкретным объектом, и проверяем эти правила прямыми HTTP-запросами и тестами.

## 1. Запуск на Windows в VS Code

Нужны .NET SDK 10 и Git. Docker, CI и сканеры для этого занятия не нужны. SDK и зависимости ограничены `global.json` и файлами `packages.lock.json`.

Откройте в VS Code именно папку `s07-access-control`: в ней лежат `TrackerApi.slnx`, `requests.http`, `src` и `tests`. Установите рекомендованные расширения C# Dev Kit и REST Client (`humao.rest-client`). Откройте Terminal → New Terminal; выберите PowerShell. Из корня объекта выполните:

```powershell
dotnet --version
dotnet restore --locked-mode
dotnet test
```

Ожидаются **16 пройденных и 3 пропущенных теста**. Пропущенные проверки — учебные упражнения. Штатный зеленый набор не доказывает отсутствие нарушений доступа.

В первом терминале запустите приложение:

```powershell
dotnet run --project src/TrackerApi --urls http://localhost:8080
```

Оставьте терминал открытым: он занят сервером. В дереве файлов слева откройте `requests.http`. Над блоком 0, содержащим `GET {{baseUrl}}/health`, нажмите небольшую надпись **Send Request**. Справа откроется ответ: `200 OK`, `{"status":"ok"}`. Если надписи нет, откройте расширения через Ctrl+Shift+X, найдите REST Client от Huachao Mao и установите его, затем заново откройте файл `.http`.

Для проверки только запуска можно открыть `http://localhost:8080/health` в браузере. Для остальных упражнений используйте файл запросов: там передается учебная личность пользователя. Домашней веб-страницы и Swagger у приложения нет.

Тесты выполняйте во втором терминале. Они запускают собственный сервер и собственное хранилище для каждого тестового случая; процесс на 8080 им не нужен. После изменения кода остановите ручной API через Ctrl+C и снова выполните `dotnet run`.

## 2. Учебная модель

`X-User` задает уже определенную личность. Роль и подразделение сервер берет из своего справочника. Это учебная подстановка, а не реализация аутентификации. Не используйте этот способ определения личности в собственном продукте. Изменение `X-User` переключает тестового пользователя; мы сравниваем поведение API под разными пользователями.

Пользователи:

- `alice` — заявитель, `sales`;
- `bob` — заявитель, `sales`;
- `carol` — исполнитель, `sales`;
- `dave` — исполнитель, `logistics`;
- `mgr` — руководитель, `sales`.

Если `X-User` отсутствует или логин неизвестен, защищенные маршруты возвращают `401`. В отличие от старой заготовки, alice по умолчанию не подставляется. `/health` открыт без заголовка.

Начальные обращения: №1 — alice, `sales`, неисправность ноутбука; №2 — bob, `sales`, доступ к VPN; №3 — alice, `sales`, зарплатный вопрос; №4 — dave, `logistics`, проблема сканера. Вложения: №10 относится к обращению №3; №11 — к №2. Данные учебные, в том числе зарплатный текст.

Правила:

- Заявитель читает только свои обращения. Совпадение подразделения не дает ему доступ к обращениям других заявителей.
- Исполнитель и руководитель читают обращения своего подразделения.
- Закрывать обращения могут исполнитель и руководитель только в своем подразделении. Заявитель не закрывает даже собственное обращение.
- Вложение доступно тем, кому разрешено читать его родительское обращение.
- Недоступный для чтения и отсутствующий объект на исправляемых маршрутах получают `404`. Пользователь, которому объект виден, но действие закрытия запрещено, получает `403`.
- Отказ в изменении состояния означает, что статус обращения действительно не изменился.

Статусы ответа — часть согласованного поведения этого объекта. Сами по себе коды 403 или 404 не заменяют проверку прав. Иной контракт в своем продукте обосновывается отдельно.

## 3. Работа на занятии

### Д1. Чтение чужого обращения — показ и повторение

Выполните запросы 1–6. Сравните список и прямое чтение. Сначала убедитесь, что обращение №2 существует и доступно bob, затем выполните запрос к нему под alice. Запишите пользователя, объект, ожидание и фактический ответ. Найдите причину в обработчике `GET /issues/{id}`.

В `tests/TrackerApi.Tests/AccessTests.cs` снимите `Skip` у `Requester_Cannot_Read_Foreign_Issue` и выполните:

```powershell
dotnet test --filter FullyQualifiedName~Requester_Cannot_Read_Foreign_Issue
```

До исправления тест должен падать на выдаче чужого обращения, после — проходить. Повторите штатный доступ владельца и сотрудника своего подразделения. Если все активные проверки проходят, итог — 17 пройденных, 2 пропущенных.

### Д2. Закрытие без полномочий — совместно

Перезапустите приложение, чтобы все обращения снова имели `status: open`. Выполните запросы 7–11. Проверяйте и ответ операции, и сохраненный статус отдельным чтением. Сформулируйте два независимых ограничения: допустимая роль и допустимое подразделение.

Допишите `Requester_Cannot_Close_Own_Issue`, удалите `NotImplementedException`, снимите `Skip`. Нужны отказ заявителю на свое обращение, неизменность статуса и проверка исполнителя чужого подразделения. Используйте точные ожидаемые статусы: ошибка сервера не подтверждает корректный отказ.

```powershell
dotnet test --filter FullyQualifiedName~Requester_Cannot_Close_Own_Issue
```

Наблюдайте падение до исправления. После изменения повторите тест, затем штатное закрытие через запросы 12–13 и весь набор. Итог — 18 пройденных, 1 пропущенный.

### Д3. Другой путь к данным — самостоятельно

Основное чтение обращения уже ограничено. Жалоба: «Чужие сведения все равно удается получить через вложения». Запрос 14 — штатный пример. В месте 15 напишите собственный запрос, подтвердите или отклоните жалобу и пройдите полный цикл. Не меняйте пользователя между проверками основного и смежного пути.

Закончите `Requester_Cannot_Read_Foreign_Attachment`: подтвердите существование и разрешенный доступ, проверьте отказ неправомочному пользователю и отсутствие содержимого в ответе. Снимите `Skip` после завершения теста. После исправления должны работать вложения для владельца и правомочного сотрудника. Итог учебного набора после трех задач — **19 пройденных, 0 пропущенных**.

Падение на `NotImplementedException`, ошибке сборки или запуске сервера не является воспроизведением нарушения доступа.

## 5. Повторная демонстрация и затруднения

Все обращения хранятся в памяти процесса. **Ctrl+C и повторный запуск возвращают исходные данные**, включая `open`, но сохраняют исправления исходного кода. Скрипт сброса и SQLite здесь не нужны. Для новой группы возьмите свежую стартовую копию либо подготовленный исходный commit.

Если `dotnet` не найден, установите SDK 10 и откройте новый терминал. Если занят порт 8080, запустите на 8081 и измените `@baseUrl` в `requests.http`. Если ответ не изменился после правки, перезапустите ручной API. Если NuGet не восстановил пакеты, прочитайте первую ошибку источника; это не ошибка доступа приложения.

Резерв для быстрых — `/issues/{id}/exists`, запросы 18–19. Он остается отдельной намеренно дефектной задачей после Д1–Д3. Зелёный учебный набор не означает, что исправлены все маршруты приложения. `reserve/` содержит неподключенный фрагмент для дополнительной тренировки; он не заменяет свидетельство своего проекта.
